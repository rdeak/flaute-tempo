# Digital Flute Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fourth "Flute" tab where a child presses note keys that sound for as long as they are held, sees the fingering on the tuner's flute drawing, and builds a line of notes that one Play button plays back.

**Architecture:** A pure-Kotlin `Tune` (notes with held lengths, encoded to one preference string) and a pure-Kotlin `SustainedToneSynth` (attack / sustain / release envelope over the tuner's flute timbre) sit under a new streaming `FluteTonePlayer` that runs an `AudioTrack` on its own thread, after `AudioTrackMetronomePlayer`. `FluteViewModel` (Activity-scoped) owns the held key, the tune and playback in a `FluteUiState` StateFlow, opens the player when the tab is visible and closes it when it is not. `FluteContent` is the stateless, tested composable: the name, the `FingeringDiagram`, the scrolling `TuneLine`, the octave-row `FluteKeys` and the Play row.

**Tech Stack:** Kotlin, Jetpack Compose + Material 3, Hilt, `AudioTrack` (streaming, float PCM), SharedPreferences, JUnit 4 unit tests with `kotlinx-coroutines-test`, Compose UI tests on the headless emulator `Medium_Phone_API_37.0` (boot with `-no-audio`).

**Spec:** `docs/superpowers/specs/2026-10-23-digital-flute-design.md`

## Global Constraints

- No commits: this repository's CLAUDE.md forbids the agent committing; every change stays in the working tree for the user.
- Keys offered: `StaffNotes.ALL` (MIDI 60, 62, 64, 65, 67, 69, 71, 72, 74, 76, 77, 79, 81, 83, 84), in three octave rows of 7, 7 and 1. Fingerings from `FluteFingerings.keysFor`.
- Tune constants: `MAX_NOTES = 200`, `MIN_NOTE_MS = 300`, `MAX_NOTE_MS = 2000`, `GAP_MS = 80`. Pauses between notes are not recorded; the decoder ignores an optional third field per note.
- Envelope: attack 30 ms, release 120 ms, retrigger fade 10 ms; timbre = `ReferenceToneSynth`'s harmonics (1.0, 0.3, 0.1); volume `TunerViewModel.REFERENCE_TONE_VOLUME` (0.8f) into a player peak of 0.6f, as the reference tone.
- Screen-reader activation of a key sounds it for `ACTIVATED_MS = 500`. Erase repeats after 400 ms, every 120 ms, while held.
- Layout: name row 72 dp (the notes tab's 64 sp hero style), flute 56 dp, tune line 48 dp, key rows at least 64 dp, Play row 64 dp, 12 dp side padding, 4 dp between keys. No screen scrolling when the content fits; otherwise the whole screen scrolls and the keys keep 64 dp.
- Every user-visible string in both `values/strings.xml` and `values-hr/strings.xml`; Croatian in the informal singular; note names via `noteLabel` (C4 / c1). No numbers or jargon on the screen.
- No new dependencies, drawables or fonts; icons are hand-built paths in `AppIcons`. Colours only from the theme (`surfaceVariant` peach, `secondaryContainer` teal, `tertiaryContainer` yellow, `primary` coral).
- Logging through `Logger` under a new `LogTags.FLUTE = "FA.Flute"`; never `android.util.Log`.

## Review Focus

1. A stored tune with notes the keys do not offer, junk entries or over-long held lengths (an old build, corrupt prefs): the tab must open with a tune it can play. Tests in Task 1 (`decode drops what it cannot read and ignores a pause field`) and Task 5 (`a stored tune is restored and sanitized`).
2. Two fingers down: lifting the older key, which no longer sounds, must not silence the newer one or corrupt its length. Tests in Task 5 (`the newest press wins`, `releasing a key that is not sounding is ignored`).
3. Leaving the tab mid-hold or mid-playback: silence at once, the player closed, the tune kept with the held note's length recorded. Test in Task 5 (`leaving the tab silences the flute but keeps the tune`).
4. The cap: a press at 200 notes sounds and shows the note but is not appended, and its release must not touch the tune. Test in Task 5 (`at the cap a press still sounds but is not added`).
5. A note change while one sounds, a note off, and a note on from silence must not click. Test in Task 3 (`no step at note on, note off or a new note while sounding`).
